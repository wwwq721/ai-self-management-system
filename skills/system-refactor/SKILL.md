# 治理系统体检

治理系统（System）是一个整体：一个文件改了，其他文件要同步体现、遵守、索引；凡存在约束、依赖或传导关系的治理文件，还要互相满足适用的定义和约束，而不只是彼此不冲突。体检是只读审计——先跑被审文件自己的规则（OPERATIONS「自指一致性」：审查也是操作），产出发现报告与修法建议。规则本体在各治理文件，本 skill 只编排检查项，不重复规则内容。

- [../../FREEDOM.md](../../FREEDOM.md)：区分总纲、自由与重要在每次对话中生效（写作检查）。

## 核心前提

- **治理文件的编写规则先于 skill-creator**（OPERATIONS「文件 frontmatter 规范」）：根治理文件不是 skill，skill-creator 的 BP 只适用于 skill。
- **仅用户手动触发**：本 skill 只在用户明确要求整体体检时使用；不替代日常验证、单文件检查或机械 lint，也不作为自动周期任务。
- **只读审计**：体检不改文件——发现交报告，修法建议按减少优先（改/删，不是加），是否修由用户定。
- **审计先跑被审文件自己的规则**：引用关系分类、自指、frontmatter（OPERATIONS「自指一致性」）。
- **相互符合性**：治理文件之间存在约束、依赖或传导关系时，不只检查有没有冲突或是否同步；要逐项核对关系两端是否相互满足适用要求：被约束文件是否满足约束方的定义与规则，约束方是否符合自身定位及体系中对它生效的其他要求，且双方关系没有造成定义、范围或作用上的失真。核对依据以当时体系中的实际权威定义和生效要求为准，不预设固定的文件名、字段或概念名称；没有关系的文件不强行互相套用。
- 体检必须综合所有实际适用的目的、规则、运行条件与例外，验证其共同作用的结果；未完成组合推导或缺少证据，不得判定通过。

## 体检目标与审计模型

整个治理体系的目的是为了更好地管理 AI 的各个“手脚”（即 MCP、Skill 和 Markdown 等可调用、可加载、可组合的能力资源）以及记忆等认知资源，并提升 AI 的思考能力。不同资源可根据其类型、用途和影响采用不同的管理方式；体检不为任何单个文件或机制预先规定职责，而是检查现有规则能否共同服务这一目标。

审计时围绕下面的能力闭环观察体系效果：

```text
用户目标
-> 理解目标与情境
-> 判断风险与可用能力
-> 选择并使用合适的能力资源
-> 执行
-> 观察、核查与验证
-> 根据结果调整判断
```

重点检查以下问题：能力资源是否容易被发现、理解、选择、调用、组合和维护；规则是否减少冲突、重复和无效认知负担；治理约束是否帮助 AI 形成更好的判断并完成核查，而不是只增加形式复杂度；以及各项机制在实际协作中的相互作用，是否促进而非妨碍上述目标。体系中承担协调、路由、约束或其他作用的机制，均按其在整体中的实际效果检查，不在本 skill 中预先规定其用途或边界。

## 体检流程

0. **范围与自身约束**：先完整读取本 skill、用于界定成员范围的 README，以及每个随后纳入体检范围的文件；先对本 skill 和每个被审文件执行其自身的审计约束（引用关系分类、自指、改动前告知如适用、frontmatter 等），再评估其内容。不得先凭全量清单或旧摘要对文件作结论。
1. **全量清单**：在第 0 步完成后，按 README 列出全部成员（根文件＋治理型 skill）。
2. **机械层**：引用关系分类（必要引用是否确实必要、提示或导航是否被误写成依赖或权威关系）、frontmatter（title/summary/importance）、名单 vs 实际文件、内部引用存在性、悬空引用（区分"真实引用 vs 示例代码块"——教学示例里的虚构文件名不是悬空引用）。
3. **体系作用层**：沿“目标—理解—判断—能力使用—执行—核查验证—调整”闭环，检查治理文件、Skill、MCP 等资源是否共同改善能力管理和 AI 的思考质量，而不是只检查形式完整性。
4. **机制效果与相互符合层**：检查体系中实际存在的协调、路由、约束或其他机制在整体协作中的作用，识别冲突、重复、遗漏、过度复杂或其他妨碍目标的问题；依据当时体系中的实际权威定义和生效要求，逐项核对相关关系两端是否相互满足，不把“无冲突”当作“相互满足”；不预设固定的字段、文件名或概念名称，没有关系的文件不强行互相套用。不在本 skill 中替这些机制另定用途、层级或边界。
5. **传导层**：近期新增/修改的规则，是否在相关文件被体现/遵守/索引（治理系统整体性，最容易漏）。
6. **残留层**：旧定位词、旧章节名、旧标题全量 grep。
7. **编号引用**：章节号、Step 编号、交叉引用逐一核对（重排后漏改是历史教训 T13）。
8. **双写与归属**：同一规则是否多文件重复定义；必要引用的权威归属是否清楚（单一源——引用不复述，指向不复述）。
9. **改进空间**：待批准规则是否已落地（如 T 记录"待批准"）；FUTURE 未成型词是否已有答案；冗余节；失效地图（summary 与内容不符）；被引用度极低的成员是否该合并或废弃。
10. **报告**：按文件列发现（属实 / 部分属实 / 无），给减少优先的修法建议。

## 常见坑

- 传导断裂：迁移后相关引用处没同步（reflection-evolution 引 MEMORY 旧结构就是实例）。
- 示例代码块被当假入口：skill 教学示例里的虚构文件不是悬空引用。
- 旧定位词残留："长期记录"这类旧表述留在其他文件。
- 修法变加法：把"缺索引"误判成需要加，实际引用链已覆盖。
- 体检变修改：体检是只读审计——发现与修法进报告，不直接改文件。
